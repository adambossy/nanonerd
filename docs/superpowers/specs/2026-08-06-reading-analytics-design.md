# Reading Analytics — Design

**Date:** 2026-08-06
**Status:** Approved (user waived spec review)
**Builds on:** `2026-08-04-reader-design.md`

Track actual reading behavior — active time per article, per topic, and
overall — and surface it as a stats page plus an agent-skill digest, so the
user can see what they gravitate toward and what they save but ignore
(e.g. security posts saved eagerly, never opened). Measure and report only:
no nudges, no reprioritization (the data feeds a future reprioritizer).

## Decisions made during brainstorming

- **Measurement:** active-time sessions, client-accumulated (approach "b").
  Active = tab visible AND user interaction (scroll/mouse/key/touch) within
  the last **30 seconds** (idle threshold). The client syncs its counter
  every **5 seconds** (user changed from 30s) and beacon-flushes on close.
- **Surfaces:** a `/stats` page in the web app (charts + tables, no AI),
  plus an **agent skill** (`.claude/skills/reading-digest/`) — the AI digest
  is NOT baked into the web app. The skill produces **3–5 recommendations
  on what to dig into next**.
- **Scope:** measure + report only.
- **Topic attribution:** a session's time counts in full toward each of the
  article's categories (overlap is deliberate and labeled). Articles with no
  categories go in an explicit `(uncategorized)` bucket.

## Data model

```
reading_sessions:
  id, article_id (FK -> articles.id, ondelete CASCADE, indexed),
  started_at (tz), last_active_at (tz), active_seconds (int, default 0)
```

One row per continuous visit to the reader page. Existing read-progress
tracking (chunk read_at) is untouched; sessions are a parallel signal.
Alembic migration autogenerated as before.

## API

- `POST /api/articles/{id}/sessions` → `{id}` — creates a session
  (404 if article missing).
- `POST /api/sessions/{id}` body `{active_seconds}` → `{id, active_seconds}`
  — monotonic update: server stores `max(stored, submitted)` and bumps
  `last_active_at` (404 if session missing).
- `GET /api/stats` → all aggregation server-side:
  - `totals`: `active_seconds`, `articles_saved`, `articles_finished`
    (percent_read >= 95), `words_read` (sum of read chunks' words).
  - `topics[]`: `name`, `saved`, `read_through` (mean percent_read, 1
    decimal), `active_seconds` — one row per category plus
    `(uncategorized)`; sorted by active_seconds desc, then saved desc.
  - `daily[]`: last 30 days, `{date: "YYYY-MM-DD", active_seconds}`,
    aggregated in Python from sessions (dialect-proof), missing days
    included as 0, oldest first.
  - `top_articles[]`: up to 10 by active_seconds desc where > 0:
    `{id, title, active_seconds, percent_read}`.

Stats live in a new `stats.py` router module (same `/api` prefix) to keep
`api.py` focused; session endpoints join the existing `api.py` router.

## Frontend

- `web/src/reader/useReadingSession.ts` — hook mounted by the Reader page
  once the article loads: creates the session, accumulates active
  milliseconds on a 5s tick (visible + interacted within 30s), syncs when
  the whole-second counter advances, re-syncs on failure, beacon-flushes on
  pagehide/visibility-hidden/unmount. Fire-and-forget; losing a sync costs
  ≤5s of credit.
- `web/src/pages/Stats.tsx` at route `/stats`, linked from the top nav on
  Home: overview tiles (total time, saved, finished, words read),
  time-by-topic horizontal bar chart, saved-vs-read topic table (where the
  ignored-bucket pattern jumps out), 30-day daily sparkline, top-articles
  list linking into the reader. All charts hand-rolled SVG; no chart
  library. Note under the topic chart: "articles can count in several
  topics".

## Agent skill: reading-digest

`.claude/skills/reading-digest/SKILL.md` (repo-level skill, versioned
prose). When invoked, the agent:

1. Fetches `GET http://localhost:8000/api/stats`; if the server isn't
   running, computes the same numbers directly against the DB via
   `uv run python` (the skill contains the snippet).
2. Analyzes gravitation vs. neglect: topics with high time/read-through vs.
   topics saved-but-untouched. Frames neglected topics as an open question —
   "surface it more, or admit you don't care?" — never a verdict.
3. Outputs **3–5 concrete recommendations on what to dig into next**, each
   tied to a specific article or topic with the evidence (e.g. "finish
   <article>, you're 70% through your top topic"; "security: saved 5, read
   0 — read one this week or archive the bucket").

No digest endpoint, button, or API-key plumbing in the web app.

## Error handling

Session posts fire-and-forget with retry-on-next-tick; stats endpoint is
read-only aggregation; skill degrades to direct-DB mode when the server is
down.

## Testing

API tests with seeded fixed-timestamp sessions: session create/404,
monotonic update (lower value ignored), stats math (topic attribution incl.
uncategorized, finished threshold, daily rollup with zero-fill, top
articles). Frontend verified by build type-check + browser smoke, per house
style.

## Out of scope

Nudges/badges, reprioritization, scroll-depth heatmaps, digest persistence.
